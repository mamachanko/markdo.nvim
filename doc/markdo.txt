*markdo.txt*                  Markdown runbooks for Neovim 0.11+

Mark Do                                                        *markdo*

Requires Neovim 0.11+ and the Tree-sitter Markdown block parser. Official
Neovim releases include this parser; otherwise use :TSInstall markdown with
nvim-treesitter or install parser/markdown.so on runtimepath. No setup needed.
No keys are assigned by default. See README.md for a Lazy.nvim example.

HEALTHCHECK                                                    *markdo-health*

:checkhealth markdo
    Check Neovim 0.11+, the Markdown block parser, clipboard-provider
    availability, and terminal-run support. No setup call is required.
    With Lazy.nvim, open a Markdown buffer first or :Lazy load markdo.nvim
    so the health module is on runtimepath.

    Missing core dependencies report errors with upgrade/install advice.
    Clipboard and Run capabilities are optional and report warnings when
    unavailable. Shell diagnostics show 'shell', 'shellcmdflag', the configured
    executable, platform support, and named interpreters available on PATH.
    Only the shell named by a fence is required; installing every supported
    interpreter is unnecessary.

    The check parses a string fixture to verify task and fence node support.
    It does not change a runbook, execute its fences, or read/write clipboard
    contents. See :checkhealth vim.provider for provider-specific diagnostics.

COMMANDS                                                       *markdo-commands*

The following commands and normal-mode mappings are local to Markdown buffers,
including buffers loaded before the plugin. All use unsaved buffer contents.

:MarkDoDone                                                     *:MarkDoDone*
    Check the innermost task containing the cursor. Already checked: no action.
:MarkDoDoneNext                                                 *:MarkDoDoneNext*
    Check the current task, including ancestor roll-up, then move to the next
    unfinished task after the cursor's line. See |markdo-done-next|.
:MarkDoToggle                                                   *:MarkDoToggle*
    Reverse the innermost task containing the cursor.
:MarkDoCopy                                                     *:MarkDoCopy*
    Copy the selected fence body as characterwise text to the + register.
    Requires a clipboard provider; see :checkhealth vim.provider. No final
    newline is added. Existing blank body lines are retained. Other registers
    are untouched. Any language, including an unlabelled fence, can be copied.
:MarkDoRun                                                      *:MarkDoRun*
    Explicitly run the selected shell fence in a floating terminal.
:MarkDoNext                                                     *:MarkDoNext*
    Jump to the next unchecked task after the cursor's line.
:MarkDoPrev                                                     *:MarkDoPrev*
    Jump to the previous unchecked task before the cursor's line.
:MarkDoProgress                                                 *:MarkDoProgress*
    Show completion for the current buffer, e.g. 6/8 tasks complete (75%).
:MarkDoProgressToggle                                           *:MarkDoProgressToggle*
    Toggle inline progress beside parent tasks in the current buffer.

TASKS                                                          *markdo-tasks*

Tasks include the bullet, continuation paragraphs, nested plain lists and code
blocks. A nested checkbox owns its own scope. Ordered and unordered tasks accept
[ ], [x] and [X]. Checking writes [x]. Checkbox-like code is not a task.
Blank separators between siblings and positions outside tasks report a message.

After an actual checkbox change, checkbox ancestors are recomputed bottom up.
An ancestor checks when all descendant tasks are checked; any open descendant
reopens it. Plain list items have no checkbox state. Direct parent commands
leave descendants alone. The next descendant change recomputes its ancestors.
Manual text edits never trigger roll-up. Changes affect only checkbox characters,
preserve the cursor and form one undo step per command, including roll-up.

COMPLETE AND CONTINUE                                          *markdo-done-next*

MarkDoDoneNext combines Done and Next. It uses the innermost task containing
the cursor, checks that task, and recomputes its ancestors bottom up. All
checkbox changes form one undo step. A directly checked parent still leaves
its descendants alone; an unfinished child below the cursor can be the next
destination.

The updated buffer is parsed again for navigation. Search starts strictly
after the cursor's line, skips checked tasks and code, crosses headings and
opens destination folds. It does not wrap. An already checked task advances
without changing checkbox text or adding an undo step.

With no next unfinished task, completion remains and the cursor stays put,
with a short message. Outside a task (including a sibling separator), report
"No task at cursor" and do not change text or position. Missing parsers report
the normal dependency error. The ordinary Done command remains stationary.

See README.md for optional <leader>xj. No default key is assigned.

PROGRESS                                                       *markdo-progress*

Progress counts checkbox tasks with no checkbox descendants. Parent checkbox
states summarize their children and do not add to the count. A task with only
plain list children counts once. Checkbox text inside code is ignored. A
manually checked parent with an open child still has incomplete progress.

MarkDoProgress reads the entire current buffer, including unsaved edits. The
percentage rounds to the nearest whole number. A checklist with no tasks shows
"No tasks". The command never changes the Markdown or checkbox states.

INLINE PROGRESS                                                *markdo-inline-progress*

MarkDoProgressToggle displays subtle virtual text at the end of each checkbox
parent's line, e.g. "1/3 · 33%", using the Comment highlight. Each summary counts
leaf checkbox tasks within that parent's subtree. Nested checkbox parents have
their own summaries. Leaves, plain items and code receive no annotations.

Off by default, independently enabled per buffer. Edits (including insert-mode
and API edits), completion commands, undo and redo refresh the annotations on
the next event-loop turn. Multiple edits are coalesced into a single refresh.
Manual edits update numbers without changing checkbox state. Neither rendering
nor toggling changes the text, cursor, modified flag, or undo history.

Toggle again to hide. Changing filetype away from Markdown or unloading the
buffer disables the display. Other plugins' decorations are left alone. An
unavailable parser reports the dependency when enabling; background failures
hide stale annotations and retry on the next edit without notifications.

See README.md for the optional <leader>xv binding. No setup call is required.

require('markdo').progress([bufnr])                              *markdo.progress()*
    Quiet query for statuslines and other Lua integrations. Omit bufnr or pass
    0 for the current buffer. Returns a table with these fields:
        completed   Number of checked tasks with no checkbox descendants.
        total       Number of tasks with no checkbox descendants.
        percent     Rounded completion percentage, or nil if total is 0.
    Invalid, unloaded, or non-Markdown buffers and missing parsers return
    nil, error without a notification. Successful results are cached until
    the buffer changes; callers receive an independent result table.
    No setup or default statusline modification. See README.md for a native
    Neovim statusline example and optional <leader>xs summary binding.

NAVIGATION                                                     *markdo-navigation*

Next and Prev follow document order through the entire current buffer, across
headings and including unfinished parent and child tasks. Checked tasks and
checkbox text inside fences are skipped. The cursor lands on the opening [ of
the destination checkbox; any closed fold at that location opens.

Both commands search strictly after or before the cursor's line, skipping a
task on that same line regardless of column. From continuation text or code,
Prev can return to the containing task's checkbox. At a boundary or with no
match, a short message appears and the cursor stays put. Navigation does not
wrap, reads unsaved edits, and never changes buffer contents or checkbox state.

FENCES                                                         *markdo-fences*

Copy and Run share selection rules, in this order:
1. On or inside a fence (including either delimiter), select that fence.
2. In a task, select fences whose nearest checkbox ancestor is that task.
   A sole match is used immediately; multiple matches open vim.ui.select with
   language, opening line and first nonblank body line. Child task fences are
   excluded. Zero matches reports a message.
3. Outside tasks/fences, select the next fence outside tasks, before the next
   heading of any level. Before the first heading, search only the preamble.

Cancelling the picker does nothing. Source changes or deletion while it is open
cancel the action and request a retry. Empty or incomplete selected fences report
an error; no alternative fence is chosen. Both backtick and tilde fences work.
Delimiters, info strings, container prefixes and Markdown fence indentation are
removed. Relative indentation, comments, quotes and blank body lines remain.

TERMINAL                                                       *markdo-terminal*

On macOS and Linux, sh/bash/zsh/fish use the named executable with one -c script
argument. The first word of the info string chooses the language. The label
shell uses 'shell' and 'shellcmdflag'. Unsupported/unlabelled fences and missing
executables report a short error. A run inherits the environment and originating
window's effective cwd. All lines run together, preserving variables and cd.

One asynchronous job runs at a time. A second Run focuses it. Terminal mode
allows live input. Use CTRL-\ CTRL-N to enter terminal-buffer Normal mode:
    x   Stop the active job, keeping output visible.
    q   Close the float after exit.
Closing the float another way stops an active job and cleans up the buffer.
Output stays after exit, with status in the float title and b:markdo_exit_code.
Exit status never changes task state. Runs occur only through explicit Run.
Background job management is deferred.

TESTING                                                        *markdo-testing*

From the repository root: >
    nvim --headless -u NONE -l tests/run.lua
<
Uses the real Markdown parser, a fake clipboard provider and harmless shell
jobs. Verified with official Neovim 0.11.0 and its bundled Markdown parser.
